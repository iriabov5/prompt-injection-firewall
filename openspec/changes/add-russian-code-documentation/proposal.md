## Why

Код и тесты проекта должны быть понятны при публичном просмотре репозитория без обязательного чтения истории чата или устных пояснений. Русский KDoc/Javadoc для production-кода и русские `@DisplayName` для тестов сделают намерение классов, методов и сценариев явно видимым в IDE, отчетах тестов и code review.

## What Changes

- Добавляется требование документировать уже существующий и новый production Kotlin code русским KDoc/Javadoc.
- Добавляется требование описывать уже существующие и новые тестовые классы и тестовые сценарии через `@DisplayName` на русском языке.
- Добавляется требование не подменять документацией плохие имена: комментарии должны объяснять назначение, контракт или важное поведение, а не пересказывать очевидный код.
- Реализация бизнес-логики, HTTP-контрактов и scoring rules в рамках этого change не меняется.
- Не-цель: писать длинные tutorial-комментарии внутри каждого метода или дублировать OpenSpec в коде.

## Capabilities

### New Capabilities

- `code-documentation`: требования к русскому KDoc/Javadoc для production-кода и к поддержанию документации в актуальном состоянии.

### Modified Capabilities

- `test-coverage`: требования к тестам расширяются русскими `@DisplayName`, чтобы отчеты тестов показывали, что именно проверяется.

## Impact

- Будущая реализация затронет существующие Kotlin production files в `src/main/kotlin`, а дальнейшие изменения должны соблюдать это правило сразу при добавлении нового кода.
- Будущая реализация затронет существующие test files в `src/test/kotlin`, а дальнейшие изменения должны сразу добавлять русские `@DisplayName`.
- Возможны небольшие изменения imports в тестах для подключения JUnit 5 `@DisplayName`.
- API behavior, dependencies и runtime configuration не должны измениться.
